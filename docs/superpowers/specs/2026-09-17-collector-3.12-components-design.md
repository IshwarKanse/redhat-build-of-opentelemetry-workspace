# OpenTelemetry Collector Components for 3.12

**Date:** 2026-09-17
**Ticket:** OBSDA-1475, TRACING-6691
**Status:** Design

## Summary

Evaluation and design for new OpenTelemetry Collector components proposed for RHOSDT 3.12. Four components were evaluated; three are accepted (two new TP, one existing TP with operator improvements), one is excluded.

| Component | Type | Decision | Support Level | Upstream Stability | Open Bugs | Customer Demand |

| Log Deduplication | Processor | **Accept** | TP | Alpha | 0 | Strong (case 04523104) |

## Components Accepted

### Log Deduplication Processor (TRACING-6697)

Aggregates identical logs over a configurable time interval, emitting a single log with a `log_count` attribute. Key OCP use case: Kubernetes events deduplication for EDA and SIEM integration.

**Key config options:** `interval`, `metadata_keys` (multi-tenant), `conditions` (OTTL filtering), `include_fields`/`exclude_fields`.

**Operator impact:** None — pure processor.

**Upstream tickets to consider fixing:**
- #50851 — O(n^2) hashing in `pkg/pdatautil` (affects dedup performance)

### Syslog Exporter (TRACING-6788)

Exports logs via syslog protocol (RFC 5424/3164) to SIEM systems and compliance archival backends.

**Documentation alignment:** The OTEL docs for syslog export should reference and align with OCP Logging's SIEM support documentation. OCP Logging already provides guidance for syslog forwarding to SIEM targets — the OTEL docs should cover the same SIEM targets and configuration patterns, ensuring consistency for users evaluating or migrating between OCP Logging and OpenTelemetry. Include cross-references to OCP Logging docs.

**Key config options:** `endpoint`, `network` (tcp/udp), `protocol` (rfc5424/rfc3164), `tls`, `retry_on_failure`, `sending_queue`.

**Operator impact:** None — outbound only.

**Upstream tickets to consider fixing:**
- #49234 — Frame injection via unescaped newlines (SIEM record forgery, security-adjacent) — **high priority**
- #48041 — No backpressure with sending_queue (P1, affects reliability)

### Webhook Event Receiver (existing TP, TRACING-6641/6642)

Already TP since 3.11. For 3.12: keep as TP, add operator parser for better UX.

**Operator improvement:** Register `webhook_event` parser in `internal/components/receivers/helpers.go` with default port 8088. Currently the operator cannot auto-detect the receiver's port, forcing manual Service configuration.

**GA blockers:**
- #50893 — Panic on path misconfiguration (blocks GA)

**Upstream tickets to consider fixing:**
- #50893 — Config validation for path fields — **high priority, blocks GA**

## Component Excluded

### Logs Transform Processor (TRACING-6698 — cancel)

**Rationale:**
1. Upstream stability `development` (lowest tier) — not in any upstream distribution
2. Explicitly slated for deprecation (upstream #19775)
3. Quality issues: open bug #31140, flaky tests, single maintainer
4. The Transform Processor (GA in RHOSDT) + OTTL covers the same use cases

**Action:** Close TRACING-6698 as "Won't Do". Document OTTL-based log transformation patterns in existing Transform Processor docs instead.
