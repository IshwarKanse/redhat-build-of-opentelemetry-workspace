# OpenTelemetry Collector Components for 3.12

**Date:** 2026-09-17
**Ticket:** OBSDA-1475, TRACING-6691
**Status:** Design

## Summary

Evaluation and design for new OpenTelemetry Collector components proposed for RHOSDT 3.12. Four components were evaluated; three are accepted as new TP components in 3.12 (Log Deduplication, Syslog and Webhook Event, the latter with an operator parser improvement), one is excluded.

**Target upstream version:** 0.161.0 (bump from 0.158.0). The webhook event receiver is not in any 3.11 build, so it is new in 3.12 and is added to the distro in the same change as the other two components. Configuration facts in this design were corrected against the component sources on 2026-09-21; see `.ai/spec/what/collector-3.12-components.md` for the verified option tables.

## Components Accepted

### Log Deduplication Processor (TRACING-6697)

Aggregates identical logs over a configurable time interval, emitting a single log with a `log_count` attribute. Key OCP use case: Kubernetes events deduplication for EDA and SIEM integration.

**Key config options:** `interval`, `metadata_keys` (multi-tenant), `conditions` (OTTL filtering), `include_fields`/`exclude_fields`.

**Operator impact:** None — pure processor.

**Upstream tickets to consider fixing:**
- #50851 — O(n^2) hashing in `pkg/pdatautil` (affects dedup performance)

### Syslog Exporter (TRACING-6788)

Exports logs via syslog protocol (RFC 5424/3164) to SIEM systems and compliance archival backends.

**Documentation alignment:** The OTEL docs for syslog export should reference and align with OCP Logging's syslog documentation. OCP Logging documents syslog forwarding tested against rsyslog (RFC 3164/5424) and Splunk through HEC; it names no other SIEM products. The OTEL docs should cover the same configuration patterns (message fields, RFC modes, TLS transport), ensuring consistency for users evaluating or migrating between OCP Logging and OpenTelemetry, without claiming vendor-specific parity. Include cross-references to OCP Logging docs.

**Key config options:** `endpoint`, `network` (tcp/udp), `protocol` (rfc5424/rfc3164), `tls`, `retry_on_failure`, `sending_queue`.

**Operator impact:** None — outbound only.

**Upstream tickets to consider fixing:**
- #49234 — Frame injection via unescaped newlines (SIEM record forgery, security-adjacent) — **high priority**. PR #49239 is open upstream.

Note: #48041 (no backpressure with `sending_queue` and `block_on_overflow: true`) is a bug in the syslog **receiver**, not the exporter, and does not apply here.

### Webhook Event Receiver (new in 3.12, TRACING-6641/6642)

New in 3.12 as TP: the receiver is not in any 3.11 build (`manifest.yaml`, release notes and docs have no entry). It is added to the distro together with the other two components, superseding distro PR #153. The operator gets a parser for better UX.

**Operator improvement:** Register `webhook_event` parser (alias `webhookevent`) in `internal/components/receivers/helpers.go` with default port 8088. The operator already derives a Service port from the receiver's required `endpoint` through its generic fallback parser; the parser adds a default endpoint when `endpoint` is omitted, the OpenShift TLS profile defaults for `tls:`, and the alias. The change is made upstream first.

**GA blockers:**
- #50893 — Panic on path misconfiguration (blocks GA)

**Upstream tickets to consider fixing:**
- #50893 — Config validation for path fields — **high priority, blocks GA**

## Component Excluded

### Logs Transform Processor (TRACING-6698 — cancel)

**Rationale:**
1. Upstream stability `development` (lowest tier) — not in any upstream distribution
2. Explicitly slated for deprecation (upstream #19775)
3. Quality issues: open bug #31140, flaky tests, single maintainer
4. The Transform Processor (GA in RHOSDT) + OTTL covers the same use cases

**Action:** Close TRACING-6698 as "Won't Do". Document OTTL-based log transformation patterns in existing Transform Processor docs instead.
