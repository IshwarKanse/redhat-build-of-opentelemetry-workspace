# Pre-merge CI in release (new ART group)

What the jobs do, what the config builds and how the collector image reaches them is in [`ci-job-layout.md`](../../otel-qe-ocp-ci-tests/references/ci-job-layout.md).

## Steps for a new ART group

Work in a clone of `release` (`release/` in the workspace), on a branch from a freshly fetched `origin/main` (`git fetch origin`). Replace `<old>` and `<new>` with the old and new `rhosdt-*` versions. The new branch must exist in `openshift/open-telemetry-opentelemetry-operator` and `openshift/redhat-opentelemetry-collector`. The user has chosen to move or to copy (SKILL.md, "Move or copy: ask first").

1. **Operator config.** In `ci-operator/config/openshift/open-telemetry-opentelemetry-operator/`, rename (move) or copy (copy) `openshift-open-telemetry-opentelemetry-operator-rhosdt-<old>__art-build.yaml` to `...-rhosdt-<new>__art-build.yaml`, and set `zz_generated_metadata.branch` of the new file to `rhosdt-<new>`. Check that nothing else in the new file mentions the old version: `grep -n "<old>" <file>`. The one expected hit is the tag of the `opentelemetry-collector` base image when it is `rhosdt-<old>`: leave it for step 8. That tag must equal `promotion.to[].tag` of the old collector config; if it does not, step 8 of the previous release was skipped, so do it first. Also update the branch that the qe-agent skills name for the premerge step (`grep -rn "rhosdt-<old>" ci-operator/step-registry/openshift-observability/qe-agent/resources/skills/`, the `otel` and `otel-ui` skills); with copy, name both branches.
2. **Review the matrix.** Every test of the config names its OpenShift version (`e2e-pre-merge` and `e2e-ui-ocp-<x>-<y>` on the current GA version, `e2e-ocp-<x>-<y>[-fips|-arm64]` on the others; a test name cannot contain a dot). For the new release, check that the versions are still the ones to test: the floor of the bundle (`com.redhat.openshift.versions` in `bundle/openshift/bundle.Dockerfile`), the EUS versions in support, the current GA, the next streams. Every test is a hive claim: an `obs` pool of that version (`ls clusters/hosted-mgmt/hive/pools/openshift-observability/`, the `obs-ocp-<x>-<y>-0-amd64-*` and `obs-ocp-<x>-<y>-0-fips-*` pools; the `obs-logging-*` pools are for logging) or a shared `openshift-ci` pool (`clusters/hosted-mgmt/hive/pools/openshift-ci/`, which has arm64 and the next stream). Move a test to another version by changing its `cluster_claim.version` (and `owner` when the pool is of another owner) and its name; review its `SKIP_TESTS` and the channels of its `OPERATORS` list (Loki and Logging `stable-6.x` must exist in the `redhat-operators` catalog of that version). The arm64 test and `e2e-pre-merge` move to the current GA version when their versions leave support. See "Changing the matrix" in [`ci-job-layout.md`](../../otel-qe-ocp-ci-tests/references/ci-job-layout.md) for a version without any pool.
3. **Carry over the changes of the upstream CI.** The new branch is cut from a newer upstream operator, whose tests run in the upstream jobs of `main`: the config `openshift-open-telemetry-opentelemetry-operator-main__upstream.yaml` in the same directory and its steps (`distributed-tracing-tests-opentelemetry-upstream`, `distributed-tracing-tests-opentelemetry-ui-upstream`). Their product counterparts are the new config and the `-premerge` steps. What to sort is what changed upstream since the old product config was created:
   ```bash
   C=ci-operator/config/openshift/open-telemetry-opentelemetry-operator
   S=ci-operator/step-registry/distributed-tracing/tests
   Q=ci-operator/step-registry/openshift-observability/qe-agent/resources/skills
   SINCE=$(git log --diff-filter=AR -1 --format=%H origin/main -- "$C/openshift-open-telemetry-opentelemetry-operator-rhosdt-<old>__art-build.yaml")
   echo "SINCE=${SINCE:?no config of rhosdt-<old> on origin/main, check <old>}"
   UP=("$C/openshift-open-telemetry-opentelemetry-operator-main__upstream.yaml" "$S/opentelemetry/upstream" "$S/opentelemetry-ui/upstream")
   git log --name-only --format='%n%h %cs %s' "$SINCE"..origin/main -- "${UP[@]}" "$S/opentelemetry/premerge" "$S/opentelemetry-ui/premerge" "$Q"
   git diff "$SINCE" origin/main -- "${UP[@]}"
   ```
   The commands read `origin/main`, so they work before and after the edits of steps 1 and 4. Differences between the upstream and the product config or steps that already existed at `SINCE` are intentional; leave them unless this diff touches them. The steps of a config are the refs of its tests (`yq '[.tests[].steps.test[] | .ref // .as] | unique'`); a step without a ref, such as `install`, is defined in the config itself. Sort each change:
   - **Needed by the tests of the new branch:** tests and suites added, renamed or removed; a changed way to run them (commands, make targets, variables, timeouts, the setup of the cluster); the images they need; and changes of the config: `build_root`, `base_images`, resources, inline steps, `post` steps, and the env of the tests (`OPERATORS`, `SKIP_TESTS`, `cluster_claim`). Carry it over to the product tests of the same kind (the pre-merge `RUN_TESTS` job, the full-suite jobs, the UI job), not by test name. First check that what it uses (a test directory, a make target, a fixture Dockerfile) exists on `rhosdt-<new>` of `openshift/open-telemetry-opentelemetry-operator`, which is older than upstream `main` (`gh api "repos/openshift/open-telemetry-opentelemetry-operator/contents/<path>?ref=rhosdt-<new>"`); if it does not, leave the change for a later release. The images of the product's own components come from the ART Dockerfiles of `rhosdt-<new>` (`*.art`): a new one there is a new entry in `images`, a `dependencies` entry and a variable of the step. Test fixture images (under `tests/`) are built from the repository's Dockerfile, as upstream does. A new operator to install gets the channel check of step 2 on every OpenShift version that installs it, and a test that has no `install-operators` step (`e2e-pre-merge`) needs it added. When the variables or the setup of a `-premerge` step change, update the parts about it in the `otel` and `otel-ui` qe-agent skills (`$Q`).
   - **Upstream only:** needs an image or a component that `rhosdt-<new>` does not build or ship. Leave it out. If a test of the new branch needs it, take the test out of the product's test lists and give the reason in a comment next to `FULL_SUITE` in the `-premerge` commands, or in the PR description (`make ci-operator-config` keeps no YAML comments in the config).
   - **Already carried over:** a commit that changed the `-premerge` steps as well (the file list of `git log` shows it).
   - **Unclear:** ask the user rather than guessing.

   Example: [openshift/release#88977](https://github.com/openshift/release/pull/88977) brought a new Go test suite to the upstream jobs: a new test fixture image passed to the step as a new variable, the suite added to the test lists and run through the repository's make targets, the chainsaw directories it replaced removed from `RUN_TESTS`, and the qe-agent `otel` skill updated. A new branch that has the suite needs the fixture image, the step change and the list changes in the product config, but not the runs that use the agent images only upstream builds.

   With **copy**, the old branch keeps using the same `-premerge` steps, so every change must keep its jobs working. Put what the old branch cannot take behind a variable of the step whose default keeps the old behavior, and set it in the new config only. That includes a changed `FULL_SUITE`: a suite directory missing from a branch fails its full-suite jobs even when `SKIP_TESTS` names it. A check that a new variable is set applies only when its tests run. A new `dependencies` entry cannot be gated: ci-operator resolves every dependency of a step when it loads the config, so an image the old branch cannot build breaks all of its jobs. Put such tests in a new step that only the new config uses. With **move**, only the new branch uses the steps.
4. **Collector config.** In `ci-operator/config/openshift/redhat-opentelemetry-collector/`, rename or copy `openshift-redhat-opentelemetry-collector-rhosdt-<old>.yaml` the same way. Keep `additional_architectures: [arm64]`: the arm64 test of the operator needs it. Set `promotion.to[].tag` of the new collector config to `rhosdt-<new>` (move and copy alike), so that every branch promotes its own collector image and two branches never overwrite each other's tag. The new operator config keeps the tag of the old one in this PR, because `rhosdt-<new>` exists only after the new postsubmit has run; step 8 switches it.
5. **Review the test lists.** If test directories were added, removed or renamed on the new branch, update `RUN_TESTS` of `e2e-pre-merge` in the config and `FULL_SUITE` in `ci-operator/step-registry/distributed-tracing/tests/opentelemetry/premerge/distributed-tracing-tests-opentelemetry-premerge-commands.sh` (how the lists work: "The tests" in [`ci-job-layout.md`](../../otel-qe-ocp-ci-tests/references/ci-job-layout.md)). Then check every `RUN_TESTS` and `SKIP_TESTS` entry of the jobs against the test directories of `rhosdt-<new>` (`git ls-tree -d -r --name-only origin/rhosdt-<new> tests/` in a clone of the operator fork). A `RUN_TESTS` or `FULL_SUITE` entry that does not exist fails the job; a `SKIP_TESTS` entry (a glob) that matches nothing is ignored, so a renamed test then runs unskipped. With **copy**, change `FULL_SUITE` for the new branch only, through the variable of step 3.
6. **Regenerate the jobs.** Run `CONTAINER_ENGINE=podman make ci-operator-config jobs registry-metadata`. The generated files in `ci-operator/jobs/openshift/open-telemetry-opentelemetry-operator/` and `ci-operator/jobs/openshift/redhat-opentelemetry-collector/` must be for the new branch (and, with copy, still for the old one). With move, if the files of the old branch (`...-rhosdt-<old>-presubmits.yaml`, `...-postsubmits.yaml`) are still there, delete them and run `make jobs` again.
7. **Open the PR and rehearse** with `/pj-rehearse` comments, the always-run jobs and the optional ones that changed:
   ```
   /pj-rehearse pull-ci-openshift-open-telemetry-opentelemetry-operator-rhosdt-<new>-art-build-e2e-pre-merge
   /pj-rehearse pull-ci-openshift-redhat-opentelemetry-collector-rhosdt-<new>-images
   ```
   When step 3 or 5 changed a `-premerge` step or `FULL_SUITE`, also rehearse one full-suite `e2e-ocp-*` job of the new branch, and its `e2e-ui-ocp-*` job when the UI step changed; with copy, rehearse one full-suite job of the old branch too. For `NoClusters` in the log, see Step 3 of [`/otel-qe-ocp-ci-tests`](../../otel-qe-ocp-ci-tests/SKILL.md).
   The collector image of this rehearsal is still the one of the previous branch (the old tag, step 4). The rehearsal then tests the new operator against the previous collector. That is expected, so do not chase a collector version mismatch here.
8. **After the PR merges, promote the collector image from the new branch and switch to it.** The collector postsubmit runs on a push to the new collector branch; if there is no push to wait for, trigger it through gangway ("Promoting the collector image" in [`ci-job-layout.md`](../../otel-qe-ocp-ci-tests/references/ci-job-layout.md)). When it ends in `SUCCESS` (`get_prow_job_history` of the openshift-ci MCP server, `/otel-openshift-ci`), the tag `rhosdt-<new>` exists. Open a second PR that sets the tag of the `opentelemetry-collector` base image of the new operator config to `rhosdt-<new>`, run `make jobs`, and rehearse `e2e-pre-merge` of the new branch and its arm64 job on it (the arm64 job needs the arm64 image in the tag). Then check the first real pre-merge run on a PR to the new operator branch.

With copy, when the last release of the old version is out, remove its operator and collector configs and their generated jobs in a separate PR. In the same PR, make the values that the new config sets for the step variables of step 3 the new defaults and remove them from the config, and remove the old branch from the qe-agent skills.

The ART configuration in `ocp-build-data` and the Konflux build configuration in `konflux-release-data` are not part of this skill; see `/otel-art-reference`.
