# Pre-merge CI in release (new ART group)

What the jobs do, what the config builds and how the collector image reaches them is in [`ci-job-layout.md`](../../otel-qe-ocp-ci-tests/references/ci-job-layout.md).

## Steps for a new ART group

Work in a clone of `release` (`release/` in the workspace), on a branch from `origin/main`. Replace `<old>` and `<new>` with the old and new `rhosdt-*` versions. The new branch must exist in `openshift/open-telemetry-opentelemetry-operator` and `openshift/redhat-opentelemetry-collector`.

1. **Operator config.** In `ci-operator/config/openshift/open-telemetry-opentelemetry-operator/`, rename `openshift-open-telemetry-opentelemetry-operator-rhosdt-<old>__art-build.yaml` to `...-rhosdt-<new>__art-build.yaml` and set `zz_generated_metadata.branch` to `rhosdt-<new>`. Check that nothing else in the file mentions the old version: `grep -n "<old>" <file>`.
2. **Review the matrix.** Every test of the config names its OpenShift version (`e2e-pre-merge` and `e2e-ui-ocp-<x>-<y>` on the current GA version, `e2e-ocp-<x>-<y>[-fips|-arm64]` on the others; a test name cannot contain a dot). For the new release, check that the versions are still the ones to test: the floor of the bundle (`com.redhat.openshift.versions` in `bundle/openshift/bundle.Dockerfile`), the EUS versions in support, the current GA, the next streams. Every test is a hive claim: an `obs` pool of that version (`ls clusters/hosted-mgmt/hive/pools/openshift-observability/`, the `obs-ocp-<x>-<y>-0-amd64-*` and `obs-ocp-<x>-<y>-0-fips-*` pools; the `obs-logging-*` pools are for logging) or a shared `openshift-ci` pool (`clusters/hosted-mgmt/hive/pools/openshift-ci/`, which has arm64 and the next stream). Move a test to another version by changing its `cluster_claim.version` (and `owner` when the pool is of another owner) and its name; review its `SKIP_TESTS` and the channels of its `OPERATORS` list (Loki and Logging `stable-6.x` must exist in the `redhat-operators` catalog of that version). The arm64 test and `e2e-pre-merge` move to the current GA version when their versions leave support. See "Changing the matrix" in [`ci-job-layout.md`](../../otel-qe-ocp-ci-tests/references/ci-job-layout.md) for a version without any pool.
3. **Collector config.** In `ci-operator/config/openshift/redhat-opentelemetry-collector/`, do the same rename for `openshift-redhat-opentelemetry-collector-rhosdt-<old>.yaml`. Leave the `promotion` stanza and `additional_architectures: [arm64]` as they are: the image is promoted to the static tag `redhat-otel-collector` whichever branch built it, so the operator config needs no change for the new branch, and the arm64 build is what the arm64 test of the operator needs.
4. **Review the test lists.** If test directories were added, removed or renamed on the new branch, update `RUN_TESTS` of `e2e-pre-merge` in the config and `FULL_SUITE` in `ci-operator/step-registry/distributed-tracing/tests/opentelemetry/premerge/distributed-tracing-tests-opentelemetry-premerge-commands.sh` (how the lists work: "The tests" in [`ci-job-layout.md`](../../otel-qe-ocp-ci-tests/references/ci-job-layout.md)). A directory that does not exist on the branch fails the job.
5. **Regenerate the jobs.** Run `CONTAINER_ENGINE=podman make ci-operator-config jobs registry-metadata`. The generated files in `ci-operator/jobs/openshift/open-telemetry-opentelemetry-operator/` and `ci-operator/jobs/openshift/redhat-opentelemetry-collector/` must be for the new branch. If the files of the old branch (`...-rhosdt-<old>-presubmits.yaml`, `...-postsubmits.yaml`) are still there, delete them and run `make jobs` again.
6. **Open the PR and rehearse** with `/pj-rehearse` comments, the always-run jobs and the optional ones that changed:
   ```
   /pj-rehearse pull-ci-openshift-open-telemetry-opentelemetry-operator-rhosdt-<new>-art-build-e2e-pre-merge
   /pj-rehearse pull-ci-openshift-redhat-opentelemetry-collector-rhosdt-<new>-images
   ```
   For `NoClusters` in the log, see Step 3 of [`otel-qe-ocp-ci-tests`](../../otel-qe-ocp-ci-tests/SKILL.md).
   The collector image of this rehearsal is still the one of the previous branch, because the postsubmit that promotes it does not exist before the PR merges and the tag is static. The rehearsal then tests the new operator against the previous collector. That is expected, so do not chase a collector version mismatch here.
7. **After the PR merges, promote the collector image from the new branch.** The collector postsubmit runs on a push to the new collector branch; if there is no push to wait for, trigger it through gangway ("Promoting the collector image" in [`ci-job-layout.md`](../../otel-qe-ocp-ci-tests/references/ci-job-layout.md)). Then check the first real pre-merge run on a PR to the new operator branch.

The ART configuration in `ocp-build-data` and the Konflux build configuration in `konflux-release-data` are not part of this skill; see `otel-art-reference`.
